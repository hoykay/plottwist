How the app works

PlotTwist supports pasted text, PDF documents, and best-effort public job-posting URLs.

1

Input

The user provides the original job posting and final offer through paste, PDF upload, or a public URL.

2

Extract

Gemini extracts structured employment terms such as salary, PTO, bonus, title, work arrangement, benefits, and probation.

3

Compare

PlotTwist's deterministic comparison logic assigns Match, Changed, Missing, or New.

4

Explain

Findings are connected to evidence from the posting and offer so the user can inspect the exact language.

5

Clarify

Important changes become neutral questions the user may want to clarify before accepting or signing.

Architecture

Gemini handles factual extraction. PlotTwist code determines the comparison status.

The model extracts structured facts, but PlotTwist does not ask the model to decide whether a term is changed, missing, new, or matching. That classification happens in deterministic application code.

Important files

These are the best places to start when learning or extending the project.

app/page.tsx

Homepage, document input modes, validation, loading progression, failure states, comparison orchestration, and navigation.

app/results/page.tsx

Summary counts, findings, source evidence, sample/live mode, clarification questions, and results navigation.

lib/gemini.ts

Extracts structured employment terms from pasted text and text retrieved from public URLs.

lib/pdf-gemini.ts

Sends the two PDF documents directly to Gemini and extracts the same structured employment fields.

lib/compare.ts

Deterministically compares extracted terms and generates Match, Changed, Missing, and New findings.

lib/schemas.ts

Defines the shared structured extraction schema and supported employment fields.

lib/url-reader.ts

Validates and retrieves public web pages, extracts readable text, limits content size, and rejects local/private URLs.

app/api/compare/route.ts

Validates text input, calls extraction and comparison logic, and returns findings and source text.

app/api/compare-pdf/route.ts

Handles PDF validation, file-size limits, PDF extraction, and the shared comparison pipeline.

app/api/read-url/route.ts

Provides the public job-posting URL endpoint and returns readable page text for comparison.

Finding states

PlotTwist keeps the vocabulary simple so users can understand the result immediately.

Changed

The term appears in both documents but the value differs.

Missing

The posting included the term but the final offer does not.

New

The offer introduces a term that was absent from the posting.

Match

The term is present in both documents and remains consistent.

Practice to reuse

Trace one finding end to end

Pick a finding such as Salary and trace it through the code instead of reading the entire project at once.

  1. Find salary in lib/schemas.ts and see how it is represented in structured extraction.
  2. Find how Gemini is instructed to extract the salary term in lib/gemini.ts or lib/pdf-gemini.ts.
  3. Follow the salary comparison logic through lib/compare.ts.
  4. Find where the resulting Salary finding is rendered inside app/results/page.tsx.
  5. Change only the presentation of that finding, run npm run lint, and confirm the extraction/comparison logic still behaves the same.

What to remember

Model responsibility

Use Gemini to extract facts from messy documents. Keep important status decisions in predictable application logic.

Product responsibility

PlotTwist is not a legal adviser or negotiation bot. Its job is to surface evidence-backed differences worth reviewing.

Design responsibility

The interface should make changed terms obvious while always giving the user access to the source evidence behind a finding.
